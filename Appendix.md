```text

```

- Installation
- Usage / Example Code
- License
- Data description
- Project Structure (file tree)

## Step 2: README Draft

**Seed prompt**


**Key response**

A basic draft with a title, Overview, Data and Outputs sections. Installation, Example Code and License were missing.

**Refinement prompt**

```text
Add sections for Installation, Example Code, and License. Keep tone concise and professional.
```

**Key response**

- Added an Installation section (R version, `git clone` and `install.packages()` steps).
- Added a License section (MIT License).
- Tightened the wording throughout to be shorter and more concise.

**Critique/validation prompt**

```text
Review the Markdown for syntax errors and suggest 2 improvements for clarity.
```

**Key response**

Claude suggested two improvements, and I applied both:

1. Describe the data columns in a table.
2. Tag code blocks with a language (`bash`, `r`) for syntax highlighting.

**Verification:** previewed README.md on GitHub to check that headers, code blocks, lists and tables render correctly.

## Step 3: R Markdown Documentation

**Seed prompt**

```text
Here's my R script description: An R script that does SMA and RSI technical analysis on synthetic stock prices. Suggest Markdown formatting and code block examples.
```

**Key response**

- A YAML header with title, author, date and `html_document` output.
- The script's inputs as a Markdown table of parameter, value and meaning.
- Named (labelled) code chunks for each step of the script.
- Figure captions (`fig.cap`) on the chart chunks.

**Refinement prompt**

```text
Add syntax highlighting and improve section organization (e.g., # Purpose, ## Inputs, ## Outputs).
```

**Key response**

- Added `highlight: tango` to the YAML header for syntax highlighting.
- Added a floating table of contents.
- Reorganized the document into `# Purpose`, `## Inputs`, `## Processing Steps` and `## Outputs`.

**Critique/validation prompt**

```text
Is the Markdown consistent with RMarkdown best practices?
```

**Key response**

The document was consistent with R Markdown best practices; no changes were needed.

**Verification:** knitted technical_analysis.Rmd to HTML in R and checked that headers, sections, tables and code chunks render correctly.
